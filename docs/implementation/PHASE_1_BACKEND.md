# Phase 1: Backend core (mock mode)

**Objective:** the complete GlowCue HTTP API surface running in **mock mode**, with config, models, error envelope, limits and the results store, so the frontend and engine have a stable contract.
**Prompt:** [02-backend-architecture](../prompts/02-backend-architecture.md) · **Branch:** `feat/backend-api` · **Depends on:** Phase 0 · **Skill:** `/backend-engineering`

## Acceptance checks
- [ ] Every endpoint in [API_CONTRACTS](../API_CONTRACTS.md) exists. Unimplemented engine-backed ones return documented 501 or mock data.
- [ ] `POST /api/analyses` (consent required) → poll `GET /api/analyses/{id}` returns the provisional fixture after ~3 s in mock mode.
- [ ] Error envelope used everywhere. CORS is restricted. Limits and kill switch are configurable.
- [ ] Route tests cover success, validation and domain errors. pytest and ruff green.
- [ ] **Security B1/B4/B6:** `backend/.env` overrides process env for `YOUCAM_MODE` and `LIVE_ANALYSIS_ENABLED` (tested with a temporary file); the startup log shows mode/flag/key-present without the key; `LIVE_ANALYSIS_ENABLED` defaults to false. See [SECURITY_PRIVACY §4.4](../SECURITY_PRIVACY.md).

## Risks
Contract drift with the frontend. Mitigation: `frontend/src/lib/types.ts` is generated by hand in the same PR.
